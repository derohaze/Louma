# 2026-09-27

## Readable API logging + hydration warning + two wrong status codes

Request: make the backend request logs readable (they were raw pino JSON), stop the
`__root.tsx` hydration-mismatch warning, and explain the 401 on `POST /api/v1/auth/refresh`.

### Changed

- **New `back-end/src/config/logger.ts`** — `createPrettyLogStream()`, a `Writable` that parses
  pino NDJSON and prints one readable line per record. Colours only when `stdout.isTTY` and
  `NO_COLOR` is unset. Deliberately dependency-free (no `pino-pretty`: no worker thread, no
  install, and it gives the exact "METHOD PATH STATUS DURATION" shape asked for).
- **`back-end/src/app.ts`**
  - `logger.stream` = the pretty stream outside production; production keeps JSON untouched.
  - `logController: new LogController({ disableRequestLogging: true })` turns off Fastify's
    "incoming request" + "request completed" pair, replaced by one `onResponse` record per
    request (5xx logged at `error` level). Note the top-level `disableRequestLogging` option is
    deprecated in fastify 5; `logController` is the supported form.
  - `FastifyReply.errorCode` (module augmentation) is set by the error handler and read back by
    the `onResponse` line, so a rejection prints its code (`unauthorized`, `rate_limited`, ...).
  - Error handler now maps Fastify's own 4xx `statusCode` errors. Two real bugs fixed:
    `@fastify/rate-limit` returned **500 instead of 429** (its `errorResponseBuilder` must return
    an object carrying `statusCode`; the library throws the return value as-is, and it is a plain
    object, not an `Error`, so `instanceof Error` never matched), and an unparseable JSON body
    returned **500 instead of 400**.
- **`frontend/src/routes/__root.tsx`** — `suppressHydrationWarning` on `<body>`. The mismatch is
  a browser extension adding `cz-shortcut-listen` before hydration; React-only prop, never
  emitted into the HTML.

## Environment facts worth remembering

- **`bun run test:integration` is broken on this machine.** It fails with
  `querySrv ECONNREFUSED _mongodb._tcp.cluster0.xiutphn.mongodb.net` because, unlike the `dev`
  script, it does not point the resolver at public DNS. Run it the same way `dev` boots:

  ```
  node --env-file-if-exists=.env.development --import tsx \
    -e "import('node:dns').then(m=>{m.default.setServers(['8.8.8.8','1.1.1.1'])}).then(()=>import('./src/tests/database.integration.test.ts'))"
  ```

- **Ports.** Frontend dev server listens on **8080**; the Vite proxy forwards `/api` to
  `http://127.0.0.1:3001` with `changeOrigin: false`, which is why backend logs show
  `host: localhost:8080`. The API itself uses `LOUMA_API_PORT`, not `PORT`.
- `AGENTS.md` §3 lists `landing-page/` and `dashbord/` env files, but the repo has a single
  `frontend/` directory and it has **no `.env` files at all**.
- The `redact` paths in `app.ts` for `req.headers.*` and `req.body.*` are effectively dead: the
  `req` serializer emits only `{method,url,version,host,remoteAddress,remotePort}` and nothing
  ever logs a body. Harmless, but it is not doing what it looks like it does.
- Fastify's default 404 body is `{statusCode,error,message}`, not this app's
  `{error:{code,message},requestId}` envelope — `notFound()` in `shared/errors.ts` is never
  reached. Left alone; the frontend tolerates both shapes.
