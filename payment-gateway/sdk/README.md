# Louma Payments SDKs (test + live, never published to registries)

Two handwritten clients against [`../api/openapi.yaml`](../api/openapi.yaml).
Both JSON and YAML are generated by `python payment-gateway/api/build-openapi.py`
(requires PyYAML). The shared contract is:

- The client derives its environment from the API key prefix (`lma_test_` / `lma_live_`). Existing integrations may still pass `environment` explicitly.
- HTTPS `baseURL` required outside local test mode; redirects are rejected.
- Money stays an exact decimal string; the SDK never invents payment rules.
- Checkout, subscription consent and refund creation require an idempotency key.
  Reuse the same key and body after an uncertain timeout. Different intent with
  the same key returns `409 idempotency_key_reused`. Product, price, webhook and
  payment-link creation currently do not offer durable idempotency.
- Webhook verification is HMAC-SHA256 over `<timestamp>.<raw-body>` with
  `t=<unix>,v1=<hex>` signatures, ±300s/30s skew window. Deduplicate by event ID;
  delivery is at-least-once and unordered.
  Delivered JSON is `{id,type,api_version,environment,created_at,data:{id}}`;
  `data.id` identifies the payment, invoice or subscription for that event type.
- Never log secret keys; errors are typed `GatewayError` (status/code/request_id).

| Language | Path | Use |
|---|---|---|
| Node.js | `javascript/` | `LoumaClient`, `verifyWebhook`, `GatewayError` |
| Python | `python/` | stdlib-only `LoumaClient`, `verify_webhook`, `GatewayError` |

Integration examples live in [`../examples/`](../examples/). Node and Python
checkout scripts run locally with configured sandbox credentials. The HTML form
has a runnable local backend. Discord and Telegram examples require bot credentials,
their documented packages and handler registration. They are integration sketches,
not verified complete deployed bots. The bots grant access only after
`GET /v1/payments/{id}` reports `succeeded` — never on `success_url` redirect.

Creation of a recurring subscription returns a **consent checkout**. Send
`price_id` and `currency: "LMA"`; the actual subscription and mandate are created
only when the payer explicitly approves. `recurring.interval` is `month` or `year`.
Money input/payment output is a decimal string. Catalog, invoice, subscription
and refund `amount_minor` is an exact integer (10,000 minor units = 1 LMA).

Lists use only `cursor`. Pass `next_cursor` verbatim; an empty string ends the
list. Responses contain at most 50 items. `limit` and `status` filters are not
implemented. For `429`, wait for `Retry-After`; never auto-retry a mutation with a
fresh key. Errors expose status, code and request ID without embedding secrets.

Node.js and Python execution evidence and exact commands are in
[`../docs/sdk-verification.md`](../docs/sdk-verification.md). A source file or a
successful import does not mean the entire language matrix has passed.
